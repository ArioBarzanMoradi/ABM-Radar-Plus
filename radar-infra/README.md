## نصب پنل روی اوبونتو

روی **یک سرور مرکزی** با Ubuntu 24.04، Python 3.10 یا بالاتر و systemd اجرا کن. فایل‌های ساخته‌شدهٔ رابط، فونت وزیرمتن و سرویس‌دهندهٔ وب همراه بسته‌اند. **برای نصب پنل به Node.js، Docker یا حساب ChatGPT نیازی نداری.**

**۱.** مخزن را دریافت کن. در فرمان زیر `YOUR_USERNAME` را با نام کاربری GitHub خودت عوض کن. اگر نام مخزن را تغییر داده‌ای، همان نام را در هر دو خط قرار بده.

</div>

```bash
git clone https://github.com/YOUR_USERNAME/radar-infra.git
cd radar-infra
sudo bash install.sh
```

<div dir="rtl">

اگر فایل ZIP تحویلی را مستقیم به سرور فرستاده‌ای، این سه فرمان را به‌جای فرمان‌های بالا اجرا کن.

</div>

```bash
unzip radar-infra-selfhost-v1.0.0.zip
cd radar-infra
sudo bash install.sh
```

<div dir="rtl">

**۲.** نصب‌کننده نام کاربری و گذرواژهٔ مدیر را می‌پرسد. گذرواژه دست‌کم ۱۲ نویسه است. پنل به‌صورت پیش‌فرض روی `127.0.0.1:8787` اجرا می‌شود. اگر این پورت مشغول است، مثلاً `sudo bash install.sh --port 8788` را اجرا کن. نصب‌کننده سلامت سرویس را پیش از اعلام موفقیت بررسی می‌کند.

**۳.** در **ترمینال مک یا کامپیوتر خودت**، یک تونل SSH باز کن. `USER` و `SERVER_IP` حساب SSH و IP سرور مرکزی هستند. برای SSH با پورت سفارشی، `-p SSH_PORT` را به فرمان اضافه کن.

</div>

```bash
ssh -NT -L 127.0.0.1:8787:127.0.0.1:8787 USER@SERVER_IP
```

<div dir="rtl">

تا وقتی این ترمینال باز است، در مرورگر همان دستگاه **[http://127.0.0.1:8787](http://127.0.0.1:8787)** را باز کن و با حساب مدیر رادار وارد شو. اگر هنگام نصب پورت دیگری انتخاب کردی، پورت مقصد در فرمان SSH را تغییر بده. مثلاً برای پورت ۸۷۸۸ روی سرور، نگاشت `127.0.0.1:8787:127.0.0.1:8788` است. این روش با 3x-ui روی ۴۴۳ هم‌زمان کار می‌کند.

## وصل‌کردن اولین سرور

1. در پنل **افزودن سرور** را بزن. نام، کشور و IP یا نام میزبان را وارد کن. می‌توانی گروه، دامنه، پورت مورد انتظار و سرویس یا تونل هم ثبت کنی.
2. صفحهٔ همان سرور را باز کن. در **نمای کلی ← اتصال عامل لینوکس**، روی **دریافت کلید نصب عامل** و سپس **صدور کلید عامل** بزن. کلید فقط همان‌جا نمایش داده می‌شود.
3. روی **همان سروری که می‌خواهی پایش شود**، از داخل نسخهٔ استخراج‌شده یا کلون‌شدهٔ پروژه فرمان زیر را اجرا کن.

</div>

```bash
sudo bash install-agent.sh
```

<div dir="rtl">

4. اگر عامل و پنل روی یک سرور هستند، نشانی پیش‌فرض `http://127.0.0.1:8787` را قبول کن. برای عامل‌های ایران، ترکیه یا آمریکا که به پنل آلمان وصل می‌شوند، آدرس HTTPS پنل یا انتهای محلی یک تونل SSH را بده. مراحل هر دو روش در [راهنمای اتصال چند سرور](guides/operations-fa.md) آمده است.
5. کلید را در اعلان نصب وارد کن. برای نمودار پینگ، IP یا دامنه‌ای را تعیین کن که **از دید همین عامل** باید سنجیده شود. با ورود اولین نمونه، «در انتظار عامل» به «آنلاین» تبدیل می‌شود. عامل تقریباً هر ۳۰ ثانیه آمار گردآوری می‌کند. بیش از ۱۲۰ ثانیه بدون نمونه، وضعیت را آفلاین می‌کند.
6. از **عیب‌یابی و تست** ابتدا یک تست TCP به پورتی اجرا کن که می‌دانی روی مقصد پاسخ می‌دهد. مقصد باید IP یا دامنهٔ یکی از سرورهای ثبت‌شده باشد. نتیجهٔ واقعی پس از اجرای تست توسط عامل به تاریخچه اضافه می‌شود. تست ناموفق هشدار می‌سازد. نتیجهٔ نامشخص، مانند سکوت UDP، جداگانه ثبت می‌شود.

برای افزودن میزبان بعدی، مراحل ۱ تا ۵ را با **سرور و کلید جدید** تکرار کن. پنل مرکزی را یک بار نصب می‌کنی.

## آنچه اندازه‌گیری می‌شود

| مورد | منبع و تفسیر |
|---|---|
| وضعیت، CPU و RAM | زمان آخرین نمونه، اختلاف شمارنده‌های `/proc/stat` و حافظهٔ قابل استفاده در `/proc/meminfo` |
| پورت‌های شبکه | سوکت‌های TCP در حال شنود و UDP مقید در فضای شبکهٔ عامل. تست از یک میزبان دیگر، دسترسی از مسیر شبکه را بررسی می‌کند. |
| 3x-ui و WireGuard | به‌طور پیش‌فرض `x-ui.service` و رابط `wg0` یا `wg-quick@wg0.service`. برای wg-easy یا نام سفارشی، شاهد مناسب را تعیین کن. |
| Outline و تونل‌ها | واحد systemd، رابط یا پورت محلی قابل تنظیم است. برای Outline در Docker، پورت واقعی سرویس را در تنظیمات عامل معرفی کن. تا وقتی شاهدی در دسترس نباشد، وضعیت «نامشخص» است. |
| پینگ و روند | پینگ ICMP از هر عامل تا مقصد تنظیم‌شدهٔ خودش. برای مقایسهٔ چند سرور یک مقصد مشترک انتخاب کن. داده‌های گمشده در نمودار خالی می‌مانند. |
| تست دستی | پینگ، نام‌یابی DNS، اتصال TCP، پاسخ UDP و ردیابی مسیر از عامل انتخابی. WireGuard ممکن است به دیتاگرام آزمایشی پاسخ ندهد. |
| هشدار و رخداد | قطع ارتباط عامل، مصرف بالای منابع، تغییر وضعیت سرویس، خطای ثبت‌شده یا تست ناموفق. وضعیت پیگیری با دست اپراتور ثبت می‌شود. |

برای ICMP و ردیابی مسیر، در صورت نیاز روی عامل `sudo apt install iputils-ping traceroute` را اجرا کن. CPU و RAM مستقل از این دو ابزار جمع‌آوری می‌شوند. [پیکربندی سرویس‌های سفارشی و راهنمای عیب‌یابی](guides/operations-fa.md)

## صفحهٔ GitHub و دموی تعاملی

**بارگذاری اولیه.** در GitHub یک مخزن خالی با نام پیشنهادی `radar-infra` بساز. ZIP را روی مک استخراج کن. از **Add file → Upload files**، فایل‌ها و پوشه‌های **داخل** `radar-infra` را بارگذاری و Commit کن. در ریشهٔ مخزن باید `README.md`، `install.sh`، `agent/` و `docs/` کنار هم دیده شوند. روی مک برای دیدن فایل‌های مخفی مثل `.gitignore` از **⌘ ⇧ .** استفاده کن. روش Git در [راهنمای عملیات](guides/operations-fa.md) همهٔ این فایل‌ها را یک‌جا می‌فرستد.

**GitHub Pages.** در **Settings → Pages → Build and deployment**، گزینهٔ **Deploy from a branch** و سپس شاخهٔ **main** و پوشهٔ **/docs** را انتخاب کن. بعد از انتشار، دکمهٔ **Visit site** صفحهٔ فارسی معرفی پروژه را باز می‌کند. **باز کردن داشبورد نمونه** دموی تعاملی را اجرا می‌کند. Pages فقط فایل‌های عمومی `docs/` را منتشر می‌کند. پنل عملیاتی و پایگاه‌داده روی VPS خودت قرار می‌گیرند. [راهنمای GitHub برای آپلود پوشه‌ها](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository) · [انتخاب منبع GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## مدیریت و نگهداری

</div>

```bash
sudo radarctl status
sudo radarctl logs
sudo radarctl set-admin
sudo radarctl backup
```

<div dir="rtl">

حساب مدیر را با `set-admin` تغییر بده. این فرمان نشست‌های قبلی را می‌بندد. `backup` یک نسخهٔ سازگار SQLite در `/var/lib/radar-infra/backups/` می‌سازد. داده، گذرواژه و کلیدهای واقعی را خارج از مخزن نگه دار. برای به‌روزرسانی، از مخزن تازه `sudo bash install.sh` را تکرار کن. راهنمای پشتیبان‌گیری، بازیابی و به‌روزرسانی عامل در [راهنمای عملیات](guides/operations-fa.md) است.

## ساختار پروژه

| مسیر | کاربرد |
|---|---|
| `radar/`، `run.py` | سرور Python، نشست مدیر، داده‌های SQLite، تاریخچه و صف تست‌ها |
| `agent/agent.py` | عامل لینوکسی با ارتباط خروجی و تست‌های محدود شبکه |
| `frontend/` | سورس React و TypeScript همان داشبورد فارسی |
| `docs/` | صفحهٔ معرفی، دموی مستقل و فایل‌های آمادهٔ رابط |
| `deploy/` | فایل‌های systemd، صفحهٔ ورود و ورودی پنل خصوصی |
| `vendor/`، `licenses/` | سرور WSGI همراه بسته و مجوز اجزای ثالث |

برای توسعهٔ رابط، از ریشهٔ پروژه با Node.js و npm به‌ترتیب `npm ci`، `npm run typecheck` و `npm run build` را اجرا کن. خروجی به `docs/assets/` می‌رود. برای آزمون سرور و عامل، `python3 -m unittest discover -s tests` را اجرا کن.
